## 1. Назначение

REST API Memes позволяет:

1. авторизовать пользователя и получить токен доступа;
2. проверить, что токен ещё действителен;
3. управлять сущностью **Meme**: список, получение по id, создание, изменение, удаление.

| Параметр | Требование |
|----------|------------|
| Стиль API | REST |
| Формат тела | JSON |
| Базовый URL | задаётся окружением (конкретное значение вне скоупа BRD) |

---

## 2. Доступ

Все операции с ресурсами доступны **только авторизованным** пользователям.

| Заголовок | Значение |
|-----------|----------|
| `Authorization` | токен, выданный `POST /authorize` |

```http
Authorization: <token>
```

Токен получают через `POST /authorize` (поле `name`: строка).

> Как переиспользовать токены в автотестах и какие HTTP-коды ждать при отказе в доступе — в [`qa-requirements.md`](qa-requirements.md).

---

## 3. Модель данных: Meme

| Поле | Тип | Обязательное | Где используется | Описание |
|------|-----|--------------|------------------|----------|
| `id` | `int` | да | ответ API; тело **PUT** | Идентификатор мема |
| `text` | `string` | да | POST, PUT | Текст мема |
| `url` | `string` | да | POST, PUT | URL изображения / ресурса |
| `tags` | `array` | да | POST, PUT | Список тегов |
| `info` | `object` | да | POST, PUT | Дополнительные метаданные |

Правила:

- при **создании** (`POST /meme`) поле `id` в теле **не** передаётся — его назначает сервер;
- при **обновлении** (`PUT /meme/<id>`) поле `id` в теле **обязательно** и должно иметь тип **`int`**;
- BRD **не запрещает** дополнительные поля в теле запроса (сверх перечисленных).

## 4. Каталог эндпоинтов

Кратко: назначение и обязательные поля. Ожидаемые статусы ответов и негативные сценарии — в [`qa-requirements.md`](qa-requirements.md).

### 4.1. Авторизация

| Method / Path | Назначение | Тело |
|---------------|------------|------|
| `POST /authorize` | Выдать токен | `name: string` (required) |
| `GET /authorize/<token>` | Проверить, жив ли токен | — |

### 4.2. Memes (CRUD)

Все методы ниже требуют заголовок `Authorization`.

| Method / Path | Назначение | Тело (все поля required) |
|---------------|------------|--------------------------|
| `GET /meme` | Список всех мемов | — |
| `GET /meme/<id>` | Один мем по id | — |
| `POST /meme` | Создать мем | `text`, `url`, `tags`, `info` |
| `PUT /meme/<id>` | Изменить мем | `id` (`int`), `text`, `url`, `tags`, `info` |
| `DELETE /meme/<id>` | Удалить мем | — |

---

## 5. Требование к типу `id`

Поле `id` мема во всех ответах, где оно присутствует, должно иметь тип **`int`**, в том числе после успешного `PUT /meme/<id>`.

Нарушение этого требования (например, `id` как строка в ответе PUT) считается **дефектом продукта**.  
Как дефект фиксируется в автотестах — см. BUG-001 в [`qa-requirements.md`](qa-requirements.md).

---

## 6. Вне скоупа этого BRD

Следующее **не** описывается здесь (живёт в QA-документации / наблюдениях стенда):

- точные HTTP-коды ошибок (`400` / `401` / `403` / `404`);
- служебный `GET /authorize/kill/<token>`;
- правила ownership (владелец мема vs другой пользователь);
- матрица маркеров Pytest, фикстуры, Allure, CI.
